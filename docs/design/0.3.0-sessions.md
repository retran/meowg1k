# meowg1k 0.3.0 — Sessions

Status: design, not yet implemented. Companion to `0.3.0-architecture.md`,
`0.3.0-starlark-api.md`, and `0.3.0-tui.md`.

## 1. What a session is for

A session is the durable record of one agent run: every message, every tool
call, every permission decision, and everything it spent. It exists to answer
four questions, and the design is judged only against these.

1. **What did the agent actually do?** Hours or weeks later, without the
   terminal that ran it.
2. **Can I continue from here?** Add a follow-up without re-establishing
   context, and without a chat window (`0.3.0-tui.md` §1.1).
3. **Can I retry differently?** Take a run that went wrong at step 9 and rerun
   from step 8 with a different model or prompt.
4. **What was it allowed to touch, and why?** Every tool call, the decision, and
   the rule that produced it.

0.2.x answers the first partially and the other three not at all.

## 2. What 0.2.x got wrong

| Defect | Where | Consequence |
| --- | --- | --- |
| Sessions are ambient state | `m.currentSession` in `module_llm.go` | The script cannot name, pass, or inspect the session it is writing to; parentage is positional |
| Compaction mutates the log | `ctx.session.mark_obsolete(ids)` | A compacted run can no longer be replayed in full; the original messages are gone |
| Usage is stringly metadata | `llm_tokens_0_1762...` = `"prompt=91,completion=12,total=103"` | Cost cannot be summed, filtered, or charted without parsing a key and then a value |
| Metadata is the general-purpose store | `.meowg1k/lib/memory.star` stores JSON blobs under `context_*` | Untyped, unbounded, and mixed in with runtime bookkeeping in one flat namespace |
| Writes are best-effort and silent | 10 × `log.Printf("session: failed to …")` | The log can be incomplete and nothing says so — and the message corrupts the TUI on its way out |
| No resume, no fork | — | A failed run is a dead end |
| Identifiers are UUIDs | `uuid.New()` | `meow show-session 9f8e7d6c-5b4a-…` is not a thing anyone types |
| No permission record | Policy does not exist | Nothing to audit |

## 3. The log

**Append-only. Nothing is ever updated or deleted.** Every property below
depends on that one rule, which is why it is the first sentence of this section
rather than an implementation note.

```rust
pub struct Event {
    pub seq: u64,              // monotonic within the session
    pub at: Timestamp,
    pub kind: EventKind,
}

pub enum EventKind {
    Started       { task: String, agent: String, model: ModelRef, parent: Option<SessionId> },
    UserMessage   { content: BlobRef },
    Assistant     { content: BlobRef, tool_calls: Vec<ToolCall> },
    ToolCall      { id: ToolCallId, name: String, args: BlobRef },
    ToolResult    { id: ToolCallId, output: BlobRef, duration_ms: u64, error: Option<String> },
    Policy        { id: ToolCallId, decision: Decision, rule: Option<RuleId>, source: DecisionSource },
    Usage         { prompt: u32, completion: u32, cached: u32, cost_usd: Decimal },
    Compaction    { supersedes: RangeInclusive<u64>, summary: BlobRef, tokens_saved: u32 },
    Note          { level: Level, message: String },
    Finished      { stop: StopReason },
}
```

Three consequences worth stating plainly:

**Compaction supersedes, it does not delete.** A `Compaction` event names the
range it replaces. Rebuilding context for the next model call skips the
superseded range and substitutes the summary; rebuilding it for a human, or for
`session export`, walks straight past the `Compaction` event and shows the
originals. The full run survives compaction, which is what makes the second
question in §1 answerable after a long agent loop rather than only before one.

**Usage is typed, and `cached` is a column.** Prompt-cache hits are most of the
cost difference between a well-built agent and a badly built one, and a design
that cannot show them cannot be tuned. `cost_usd` is computed at write time from
the model's price table, because that table changes and a historical run should
keep the price it actually paid.

**Payloads are content-addressed.** `BlobRef` is a BLAKE3 hash into a blob
table, so an agent that reads the same 40 KB file at steps 3, 7, and 11 stores
it once. This is not premature: a single long run re-reads the same files
constantly, and a naive log is dominated by duplicated tool output.

### 3.1 Writes are not best-effort

A failed session write fails the run. 0.2.x logs the error and continues, which
produces a log that is silently wrong — the worst possible outcome for a record
whose entire job is to be trusted later. Writes are batched per turn and
committed in one transaction, so a crash loses at most the turn in flight, and
the session is marked `failed` with the reason on the next open.

## 4. Identity

```text
4f2a9c                  short id — base32, 6 chars, unique within the workspace
@last                   the most recent session in this workspace
@last-2                 the one before it
@review                 the most recent run of the `review` agent
nightly-triage          a name, when the script gave one
```

Short ids are what a person types. The full ULID stays in the database for
ordering and export; the short form is a unique prefix, extended
automatically on collision. `@`-prefixed selectors resolve at the moment of use
and are the reason `meow session show @last` is worth having at all.

Sessions live in the workspace, at `.meow/.data/sessions.db` — SQLite, WAL,
gitignored. They belong to the repository they describe, and they do not follow
the user between checkouts.

## 5. Lifecycle

```text
         ┌──────────┐
         │ running  │
         └────┬─────┘
              │
   ┌──────────┼──────────┬───────────┬──────────┐
   ▼          ▼          ▼           ▼          ▼
finished   budget    cancelled    denied     failed
```

The terminal states are exactly the `StopReason` variants from
`0.3.0-architecture.md` §4.1, plus `failed` for an engine or storage error.
There is no separate "completed" flag that can disagree with the last event:
the state _is_ the `Finished` event, and a session without one was interrupted.

A session whose process died leaves no `Finished` event. The next open detects
this and appends `Finished { stop: Failed("process exited") }` rather than
leaving a row that claims to be running forever — which is what 0.2.x's mutable
`status` column does.

## 6. Continuing and forking

Three operations, and the distinction between them is the design:

**Resume** — append to an existing session.

```bash
meow session resume 4f2a9c "now also check the error paths"
meow review --continue           # resume the last `review` session here
```

The log is replayed into a message list — honouring compaction — and the new
task is appended. The same session grows; `seq` continues.

**Fork** — branch from a prefix.

```bash
meow session fork 4f2a9c --at 8 --model fast
```

Creates a new session seeded with events 1..8 copied by reference (blobs are
shared, not duplicated) and records its origin. Step 9 onward is rerun — with a
different model, a different prompt, a narrower policy. The original is
untouched.

This is the answer to question 3 in §1, and it is the operation that makes
agents debuggable. An agent that goes wrong on step 9 of 40 currently costs a
full rerun to investigate; forking costs one step.

**Fresh** — no history. The default, and worth naming as a choice rather than an
absence: an automation invoked from CI should not pick up yesterday's context
because the two happen to share a workspace.

### 6.1 Parentage

Sub-agents (`0.3.0-starlark-api.md` §5.3) get their own session with `parent`
set. The tree is real, not flattened:

```text
4f2a9c  triage            finished   12 steps  74.4k  $0.21
├─ 8b31e4  search-agent   finished    4 steps  12.1k  $0.03
└─ c09fa2  reviewer       budget     40 steps  61.0k  $0.17
```

A parent's totals include its children's, which is how a nested budget is
enforced and how `meow session show` can tell you where the money went.

## 7. State and memory

Two scopes, neither of which is the event log.

**Session state** — `ctx.session.set/get`. Scoped to one run, stored as typed
rows keyed by name, recorded in the log as it changes so a resumed session sees
what the original left behind.

**Workspace store** — `@std//store`. Durable across runs, in its own table, with
explicit keys. This is where `.meowg1k/lib/memory.star`'s `context_*` metadata
belongs, and separating it from session bookkeeping is what stops one flat
namespace from holding both `llm_duration_ms_3_1762…` and a user's cached
analysis.

Neither is a place for large blobs. A tool result belongs in the log; an
artifact belongs in a file.

## 8. Retention

An agent log grows quickly, and a design without a GC story ends with a
gigabyte of SQLite in a repository nobody wants to clone.

```bash
meow session gc                        # apply the configured policy
meow session gc --older-than 30d
meow session rm 4f2a9c
```

```python
meow.sessions(keep_days = 30, keep_last = 200, max_size = "500MB")
```

GC deletes whole sessions, never parts of one — a half-truncated log is worse
than no log. Blobs are refcounted and collected when their last referent goes.
A named session is exempt by default, because naming one is the user saying it
matters.

## 9. Inspection and export

```bash
meow session list                      # recent runs in this workspace
meow session list --agent review --stop budget --since 7d
meow session show 4f2a9c               # the transcript, as it was rendered live
meow session show 4f2a9c --tools       # tool calls and policy decisions only
meow session show 4f2a9c --cost        # per-step token and cost breakdown
meow session export 4f2a9c --format md > triage.md
meow session export 4f2a9c --format json | jq '.events[] | select(.kind=="Policy")'
```

`show` reuses the renderers from `0.3.0-tui.md` §4, so a session replays looking
the way it looked live, and `--format json` on a stored session emits the same
event schema as a live `--format json` run. One schema, one renderer set, live
and historical.

Markdown export exists for a specific purpose: attaching an agent run to an
issue or a PR. It renders the transcript, the findings, the cost, and the
policy decisions, and it redacts values the policy marked sensitive.

## 10. Audit

Every tool call produces a `Policy` event before it runs — including the ones
that were allowed, and including the ones that were denied and therefore never
ran. `source` distinguishes a rule match from an interactive approval from a
session-scoped `always`.

```bash
meow session show 4f2a9c --tools
```

```text
  3  search.code  "retry budget"          allow   rule: search.*
  4  shell        cargo test --lib        allow   rule: shell "cargo *"
  7  shell        git push origin main    ask     approved interactively
  9  fs.write     .git/config             deny    rule: fs.write ".git/**"
```

Line 9 is the point. An agent that was talked into trying something is recorded
trying it, and the run continued because the boundary held. Without a log of
denials, a policy that works is indistinguishable from a policy that was never
tested.

## 11. Schema and migration

Versioned migrations, forward-only, applied on open, in a transaction, with the
schema version in a `meta` table — the shape 0.2.x already uses and which works.
Two additions:

- A session records the schema version it was written under, so a newer binary
  can read an older log without migrating it in place.
- Opening a database from a _newer_ binary is a clear error, not a crash.

There is no migration path from 0.2.x sessions. The event model, the identifier
scheme, and the storage layout all change, and the 0.2.x log is not something
anyone is attached to. `v0.2.1` remains installable for anyone who needs to read
an old one.
