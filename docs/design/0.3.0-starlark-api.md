# meowg1k 0.3.0 — Starlark API

Status: design, not yet implemented. Breaking against `v0.2.1`; see §11 for the
migration map. Second of four documents; `0.3.0-architecture.md` covers the
runtime that executes everything below, `0.3.0-sessions.md` the durable record
it leaves, and `0.3.0-tui.md` the command and terminal surface.

## 1. Design brief

The API exists for one job: **letting someone automate their own CLI work with
custom agents.** Everything is judged against that, and three failures of the
0.2.x API follow from having judged it against "expose the Go runtime" instead.

**Writing an agent is a paragraph, not a program.** In 0.2.x, a working agent
needs `ctx.llm.agent_turn` plus a hand-built stream handler plus a compaction
call plus a session dance — which is why `.meowg1k/lib/agent.star` exists at
all. That library is 117 lines of boilerplate every user would otherwise
rewrite, and its existence is the bug report. In 0.3.0 the common agent is a
single declaration with no handler.

**The context is a scope, not a catalogue.** `ctx` in 0.2.x carries 26 members
— `ctx.json`, `ctx.path`, `ctx.crypto`, `ctx.regexp`, `ctx.time` — none of which
have anything to do with the invocation. They are there because the object is
how the runtime hands out capabilities. Assembling it by hand in two places is
what made the two copies drift. In 0.3.0 capabilities are **imported**, and
`ctx` carries only what is genuinely per-invocation: arguments, session,
output, stdin, cancellation.

**Results are values, not strings.** `agent_turn` returning `str` means a script
cannot ask why the agent stopped, what it spent, or what it did — and when it
stops for the wrong reason, the partial work is thrown away and an error is
raised instead. Every agent invocation in 0.3.0 returns a structured result.

## 2. Layout

```text
.meow/
  meow.star          providers, models, policy, command registration
  agents/*.star      agent declarations that need control flow
  agents/*.md        agent declarations that do not — frontmatter + prompt (§5.6)
  tools/*.star       custom tools
  lib/*.star         shared helpers
  lib/*.md           shared prompt fragments, importable as strings
  .data/             sessions, cache, index (gitignored)
```

`.meowg1k/` becomes `.meow/`, matching the binary. Discovery walks up from the
working directory to the first `.meow/meow.star`, then stops — the project's
configuration wins outright, with no merging against a global one.

## 3. Loading

```python
load("@std//fs", "fs")                       # runtime module
load("@std//git", "git")
load("//lib/prompts.star", "REVIEW_SYSTEM")  # workspace-relative
load("//agents/reviewer.star", "reviewer")
```

Three schemes, one of them reserved:

| Form | Resolves to |
| --- | --- |
| `@std//<name>` | A runtime module implemented in Rust |
| `//<path>` | A file under `.meow/` |
| `@<pkg>//<path>` | A fetched package — reserved, see §10 |

Runtime modules are values you import, not members of an object you are handed.
This is the change that eliminates the two-context-builder defect: there is one
module table, consulted by the loader, and nothing to keep in sync.

## 4. Configuration

```python
# .meow/meow.star
load("@std//env", "env")

meow.provider("anthropic",
    kind = "anthropic",
    api_key = env.require("MEOW_ANTHROPIC_API_KEY"),
)

meow.model("smart",
    provider = "anthropic",
    id = "claude-sonnet-4-5",
    context = 200_000,
    max_output = 64_000,
    temperature = 0.2,
)

meow.model("fast",
    provider = "anthropic",
    id = "claude-haiku-4-5",
    context = 200_000,
    max_output = 16_000,
    temperature = 0.0,
)
```

Presets are gone. 0.2.x has three layers — provider, model, preset — where the
third exists only to name a model-plus-temperature pair, which is what a named
model already is. A `meow.model()` _is_ the named configuration; `"smart"` and
`"fast"` are models, and an agent may override any sampling parameter inline.
One indirection removed with nothing lost.

A model says what it is for. `kind` is `chat` unless it says otherwise, and an
index needs the other kind:

```python
meow.model("embed",
    provider = "anthropic",
    id = "voyage-3",
    context = 32_000,
    max_output = 0,
    kind = "embedding",
)

meow.index(model = "embed", chunk_lines = 60, overlap = 10)
```

An agent given an embedding model, or an index given a chat model, fails at
load time naming both, by [R-STAR-034]. Nothing chooses a model for an index:
`meow index build` in a workspace that declares none says to declare one, by
[R-STAR-035], because choosing is how an index gets built by one model and
queried by another.

`env.require` fails at load time with the variable's name when it is unset,
rather than producing an empty key and a 401 forty seconds into the first run.

### 4.1 Credentials live outside the project

`api_key = env.require(...)` is the escape hatch, not the normal path. Keys
belong to the machine, not the repository, and a project config that names them
puts every contributor one `export` away from a working checkout.

The normal path is a global store at `~/.meow/auth.json`, written by
`meow auth login <provider>` and never by a script:

```python
meow.provider("anthropic", kind = "anthropic")   # key resolved from the store
```

Resolution order is explicit `api_key` → the global store → a provider-specific
environment variable → a load-time error naming all three. OAuth providers
(Copilot) keep their refresh token in the same store, which is the only place a
`.star` file could not hold it anyway.

A companion `~/.meow/trust.json` records which workspaces the user has agreed to
run scripts from. A `.meow/` directory in a repository you just cloned is
executable code with tool access; the first invocation in an untrusted workspace
shows what is declared — agents, tools, and the policy they request — and asks
once.

## 5. Agents

### 5.1 Declaration

```python
# .meow/agents/reviewer.star
load("@std//fs", "fs")
load("@std//git", "git")
load("@std//search", "search")
load("//lib/prompts.star", "REVIEW_SYSTEM")

reviewer = meow.agent(
    name   = "reviewer",
    about  = "Reviews a diff for correctness defects",
    model  = "smart",
    system = REVIEW_SYSTEM,
    tools  = [fs.read, git.diff, search.code],
    budget = meow.budget(tokens = 200_000, minutes = 10, steps = 40),
)
```

That is a complete, runnable agent. No handler, no stream plumbing, no
compaction call, no session bookkeeping — the engine supplies all four, and the
terminal rendering is the default event sink.

Everything beyond the four required keys has a defensible default:

| Key | Default | Notes |
| --- | --- | --- |
| `budget` | 200k tokens, 40 steps, 30 min | A bounded run is the default; unbounded requires saying so |
| `compaction` | summarize at 80% of context, keep last 10 | Was `.meowg1k/lib/compaction.star` in userland |
| `on_tool_error` | `"report"` | Return the error to the model; `"abort"` stops the run |
| `output` | free text | A schema makes `.value` a parsed Starlark value — §7 |
| `policy` | the workspace policy | An agent may narrow it, never widen it |

### 5.2 Running

```python
r = reviewer.run(diff_text)

r.text      # str  — the final answer; populated even when stopped early
r.value     # parsed structured output, or None
r.stop      # "finished" | "budget" | "cancelled" | "denied" | "tool_aborted" | "failed"
r.ok        # bool — r.stop == "finished"
r.usage     # {prompt, completion, total, cost_usd}
r.steps     # list of steps: {index, text, tool_calls, duration_ms}
r.session   # session id
```

`r.text` being populated on every stop reason is the point. In 0.2.x, hitting
`max_iterations` raises and discards the transcript; here a budget stop is a
result you can inspect, log, or feed to another agent.

### 5.3 Agents are tools

An agent is callable as a tool, which is the whole sub-agent mechanism:

```python
triage = meow.agent(
    name   = "triage",
    model  = "smart",
    system = TRIAGE_SYSTEM,
    tools  = [search.code, reviewer],   # <- a sub-agent
    budget = meow.budget(tokens = 500_000),
)
```

The sub-agent runs in its own session, parented to the caller's, and its spend
counts against the caller's remaining budget. A fan-out cannot exceed the
top-level cap, because the cap is enforced by the engine rather than by
convention.

### 5.4 Concurrency

```python
results = meow.parallel([
    analyzer.call(task = "payments"),
    analyzer.call(task = "billing"),
    analyzer.call(task = "auth"),
])
```

`.call(...)` builds a pending invocation without running it; `meow.parallel`
executes them concurrently in Rust and returns results in order. Failures do
not poison the batch — a failed element is a result with a non-`finished`
`.stop`.

This is a deliberately narrow concurrency primitive. Starlark cannot spawn
threads, because `starlark-rust` values are not `Send`; what it can do is hand
the engine a list of _declarations_, which do cross the boundary. The
restriction is honest, and it covers the case that actually matters — fanning
one agent out over many inputs.

### 5.5 Observing a run

```python
r = reviewer.run(task, on = meow.on(
    text = lambda delta: ctx.out.write(delta),
    tool = lambda call: ctx.out.note("%s(%s)" % (call.name, call.args)),
    step = lambda step: ctx.out.step("step %d" % step.index),
))
```

Typed callbacks replace 0.2.x's single handler receiving a dict with a stringly
`kind` field that the script must switch on. Every callback is optional, and
omitting `on` entirely gets the built-in renderer — which is what nearly every
command wants and what `make_agentic_stream_handler` was working around.

### 5.6 Agents without Starlark

Most agents are a prompt, a tool list, and a budget. Requiring a `.star` file
for that is a tax on the common case, and it is the reason `pi` defines its
commands as markdown with frontmatter rather than as code.

A file under `.meow/agents/` with a `.md` extension is an agent. The frontmatter
is the declaration; the body is the system prompt:

```markdown
---
name: triage
about: Triage a failing test and propose the smallest fix
model: smart
tools: [fs.read, git.diff, search.code, shell.run]
budget: { tokens: 200000, steps: 40, minutes: 10 }
args:
  test: { type: string, positional: 0, about: "Test name or file" }
---

You triage failing tests.

Reproduce the failure before proposing anything. Read the test and the code
under test; use search.code to find callers before claiming a change is safe.
Propose the smallest change that makes the test pass without weakening it.
```

```bash
meow triage tests/retry.rs::backoff_caps
```

The two forms are the same object — a markdown agent appears in another agent's
`tools` list, is exposed on the CLI, and produces the same result struct. The
frontmatter schema is exactly the keyword arguments of `meow.agent`, so there is
one set of semantics documented once.

Reach for Starlark when the automation needs control flow: branching on whether
tests passed, fanning out with `meow.parallel`, post-processing structured
output, chaining agents through a shared session. Reach for markdown when it
does not, which is most of the time.

The same split applies to prompt fragments. A file under `.meow/lib/*.md` is
importable as a string, so shared instructions live in prose files rather than
in Starlark string literals:

```python
load("//lib/review-standards.md", "text")
```

## 6. Tools and commands

One declaration form; exposing it on the CLI and offering it to a model are
independent decisions about the same object.

```python
def _handler(ctx):
    return fs.read(ctx.args.path)

read_config = meow.tool(
    name  = "read_config",
    about = "Read a configuration file from the workspace",
    args  = {
        "path": meow.arg.string(required = True, about = "Workspace-relative path"),
    },
    run   = _handler,
)
```

```python
# .meow/meow.star — put it on the CLI as `meow review`
meow.command(review_tool)
meow.command(reviewer)      # an agent works here too: `meow reviewer "<task>"`
```

### 6.1 Arguments

```python
args = {
    "target":  meow.arg.string(positional = 0, default = "HEAD"),
    "strict":  meow.arg.bool(default = False, about = "Fail on any finding"),
    "limit":   meow.arg.int(default = 20, min = 1, max = 500),
    "format":  meow.arg.enum(["text", "json"], default = "text"),
    "paths":   meow.arg.list(meow.arg.string(), about = "Restrict to these paths"),
}
```

The same declaration produces the clap flags (`--strict`, `--limit`), the help
text, and the JSON Schema sent to the model. They cannot drift because there is
one source.

**A missing required argument is never invented.** 0.2.x fills an absent
parameter with the zero value for its type, so a model that forgets a required
`int` receives `0` and returns a confident wrong answer. Here the tool is not
invoked; the engine returns a correction to the model and the turn continues.
`None` is distinct from `0`, `""`, and `False`, and remains so all the way
through.

### 6.2 The handler context

```python
def handler(ctx):
    ctx.args.target       # parsed, validated arguments
    ctx.session           # this invocation's session
    ctx.out               # output sink: write, markdown, table, diff, step, note
    ctx.ask               # .text(), .confirm(), .select() - fails when not a terminal
    ctx.stdin             # .is_piped(), .read()
    ctx.workspace         # absolute path to the workspace root
    ctx.cancelled()       # True once the user interrupts
```

Six members against 0.2.x's twenty-six. The other twenty are runtime modules,
and they are imported.

## 7. Structured output

```python
Finding = meow.schema.object(
    fields = {
        "file":     meow.schema.string(),
        "line":     meow.schema.int(min = 1),
        "severity": meow.schema.enum(["low", "medium", "high"]),
        "summary":  meow.schema.string(max_len = 200),
    },
    required = ["file", "severity", "summary"],
)

reviewer = meow.agent(
    name   = "reviewer",
    model  = "smart",
    system = REVIEW_SYSTEM,
    tools  = [fs.read, git.diff],
    output = meow.schema.list(Finding),
)

r = reviewer.run(diff)
for f in r.value:                      # already parsed and validated
    ctx.out.write("%s:%d  %s" % (f.file, f.line, f.summary))
```

The schema builder emits provider-native structured output where available and
falls back to a validated retry loop where it is not; either way the script sees
a parsed value. 0.2.x takes a raw JSON-Schema dict and returns whatever the
model produced, leaving validation to the caller.

## 8. State

Two scopes, both engine-backed rather than reimplemented per project — the
2,500 lines of `memory.star`, `planning.star`, and `compaction.star` in 0.2.x
exist because neither scope had runtime support.

```python
ctx.session.set("plan", plan)          # this run; in the event log, replayable
ctx.session.get("plan", default = None)

load("@std//store", "store")
store.put("last_review", findings)     # durable, .meow/.data, survives runs
store.get("last_review", default = [])
```

Sessions are explicit values, not ambient state — `0.3.0-sessions.md` covers
the log, forking, retention, and audit:

```python
s = meow.session("nightly-triage")
a = investigator.run(task, session = s)
b = fixer.run(a.text, session = s.child("fix"))
```

`meow session list`, `meow session show <id>`, and `meow session resume <id>`
operate on the same log.

## 9. Policy

Declared once, enforced by the runtime on every tool call:

```python
# .meow/meow.star
meow.policy(
    allow = [
        "fs.read",
        meow.rule("fs.write", paths = ["src/**", "tests/**"]),
        meow.rule("shell", commands = ["cargo *", "git status", "git diff"]),
    ],
    ask  = [meow.rule("shell", commands = ["git push *"])],
    deny = ["http.*", meow.rule("fs.write", paths = [".git/**", "**/*.key"])],
)
```

Deny beats ask beats allow, and no match means deny — an agent cannot reach a
tool it was never granted, whatever a prompt talks it into. Under `--yes`, `ask`
degrades to `deny` rather than to `allow`, so an unattended CI run cannot
silently escalate. Every decision is recorded in the session.

An agent may narrow the workspace policy for itself and may never widen it:

```python
formatter = meow.agent(
    name   = "formatter",
    model  = "fast",
    tools  = [fs.read, fs.write, shell.run],
    policy = meow.policy(allow = [meow.rule("shell", commands = ["cargo fmt"])]),
)
```

This is the one part of the API that cannot live in a library, because a library
cannot be trusted by the thing it constrains.

## 10. Module surface

| Module | Contents |
| --- | --- |
| `@std//fs` | `read`, `write`, `append`, `exists`, `glob`, `mkdir`, `remove` |
| `@std//shell` | `run`, `capture`, `which` |
| `@std//git` | `diff`, `status`, `log`, `show`, `branch`, `stage`, `commit` |
| `@std//search` | `code` (semantic), `text` (literal/regex), `files` |
| `@std//index` | `build`, `update`, `stats`, `query` |
| `@std//http` | `get`, `post`, `put`, `delete` |
| `@std//json` `@std//yaml` `@std//toml` `@std//csv` `@std//xml` | `parse`, `encode` |
| `@std//path` | `join`, `dir`, `base`, `ext`, `rel`, `abs` |
| `@std//re` | `match`, `find_all`, `replace`, `split` |
| `@std//time` | `now`, `parse`, `format`, `since` |
| `@std//text` | `wrap`, `dedent`, `truncate`, `tokens` |
| `@std//env` | `get`, `require` |
| `@std//store` | `get`, `put`, `delete`, `keys` |

Dropped from 0.2.x: `crypto` (no automation use case justified it), `template`
(Starlark's `%` and string methods cover the need), `math` (a `.star` library,
not a runtime module), and `ui` as a general-purpose widget kit — rendering
narrows to `ctx.out`, whose job is presenting an agent's work rather than being
a TUI toolkit.

`@<pkg>//<path>` is reserved for fetched packages — pinned by version and
SHA-256, cached under `.meow/.data`, declared in a lockfile. It is item 7 of the
0.2.x TODO, it is not in the 0.3.0 scope, and the loader's scheme handling has
room for it so that adding it later is not a breaking change.

## 11. Migration from 0.2.x

Breaking, deliberately. The shipped `.meowg1k/` tree is rewritten against the
new API as the acceptance test for this design.

| 0.2.x | 0.3.0 |
| --- | --- |
| `ctx.llm.agent_turn(prompt, preset, tools, ...)` → `str` | `agent.run(task)` → result struct |
| `ctx.llm.chat(prompt, preset, ...)` | `model.ask(prompt)` — one shot, no tools |
| `ctx.fs`, `ctx.git`, `ctx.json`, … (24 more) | `load("@std//fs", "fs")` and friends |
| `meow.preset(name, model, temperature)` | folded into `meow.model(...)` |
| `meow.param(...)` | `meow.arg.string(...)` / `.int()` / `.bool()` / `.enum()` |
| `ctx.run("name", k = v)` | `tool.run(k = v)` — the tool value, not its name |
| `ctx.session.set_metadata` / `get_metadata` | `ctx.session.set` / `get` |
| `//lib/agent.star` — `run_agent_turn` | deleted; `meow.agent(...)` covers it |
| `//lib/compaction.star` | deleted; `compaction =` on the agent |
| `//lib/memory.star` | deleted; `ctx.session` and `@std//store` |
| `//lib/planning.star` | deleted; sub-agents |
| `//lib/ui_helpers.star` — stream handlers | deleted; default renderer, or `meow.on(...)` |
| `on_tool_error = "return"` | `on_tool_error = "report"` |
| `max_iterations = 50` | `budget = meow.budget(steps = 50)` |

`docs/guides/agentic-system.md` documents a `//lib/tools.star` with eighteen
tools, a `//lib/formatting.star`, and `review-agent.star` /
`orchestrator-agent.star` commands. **None of these exist in the repository.**
They are not part of the migration; the guide is stale and is deleted with the
rest of the Go-era documentation.

## 12. End-to-end example

A complete, working automation — the shape every user's first agent should have.

```python
# .meow/agents/reviewer.star
load("@std//fs", "fs")
load("@std//git", "git")
load("@std//search", "search")

SYSTEM = """You review diffs for correctness defects.

Report only defects you can demonstrate with a concrete failing input.
Use search.code to find callers before claiming a signature change is safe.
Ignore style unless it changes behaviour."""

Finding = meow.schema.object(
    fields = {
        "file":     meow.schema.string(),
        "line":     meow.schema.int(min = 1),
        "severity": meow.schema.enum(["low", "medium", "high"]),
        "summary":  meow.schema.string(max_len = 200),
    },
    required = ["file", "line", "severity", "summary"],
)

reviewer = meow.agent(
    name   = "reviewer",
    about  = "Review a diff for correctness defects",
    model  = "smart",
    system = SYSTEM,
    tools  = [fs.read, git.diff, search.code],
    output = meow.schema.list(Finding),
    budget = meow.budget(tokens = 200_000, steps = 40, minutes = 10),
)
```

```python
# .meow/meow.star
load("//agents/reviewer.star", "reviewer")

def _review(ctx):
    diff = ctx.stdin.read() if ctx.stdin.is_piped() else git.diff(ctx.args.target)
    if not diff.strip():
        ctx.out.note("nothing to review")
        return True

    r = reviewer.run(diff, session = ctx.session)

    findings = r.value or []
    if r.stop == "budget":
        ctx.out.warn("stopped on budget after %d steps; partial results" % len(r.steps))

    for f in findings:
        ctx.out.finding(f.severity, "%s:%d" % (f.file, f.line), f.summary)

    ctx.out.note("%d findings · %d tokens · $%.3f" %
                 (len(findings), r.usage.total, r.usage.cost_usd))

    blocking = [f for f in findings if f.severity == "high"]
    return not (ctx.args.strict and blocking)

meow.command(meow.tool(
    name  = "review",
    about = "Review the working tree, or a diff on stdin",
    args  = {
        "target": meow.arg.string(positional = 0, default = "HEAD"),
        "strict": meow.arg.bool(default = False, about = "Fail if any high finding"),
    },
    run   = _review,
))
```

```bash
meow review                    # review the working tree
meow review main --strict      # review against main, exit non-zero on a high finding
git diff HEAD~3 | meow review  # review a piped diff
```

The agent is eight keys. The command is a handler that reads a diff, calls the
agent, and prints. Nothing in it plumbs streams, manages history, counts tokens,
or compacts context — which is the difference this redesign is for.
