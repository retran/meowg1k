# meowg1k 0.3.0 — Architecture

Status: design, not yet implemented. Supersedes the Go architecture described in
`docs/guides/architecture.md`, which describes `v0.2.1` and will be deleted when
the Rust tree lands.

## 1. What the product is

meowg1k is a CLI automation tool. A user writes an **agent** — a model, a system
prompt, a set of tools it may call, and a budget — and invokes it from the shell
like any other command:

```bash
meow triage "flaky tests in the payments module"
git diff | meow review --strict
meow release --dry-run
```

Agents are written in Starlark, in the repository they operate on, and
versioned alongside it. The Rust binary supplies the runtime: LLM transport,
tool execution, the permission boundary, session persistence, retrieval, and
the terminal UI.

The single sentence that drives every decision below: **the agent is the unit of
abstraction, and Starlark declares it while Rust runs it.**

## 2. What 0.2.x got wrong

The Go implementation grew a Starlark runtime first and an agent loop second.
The consequences are structural, not cosmetic, and a transliteration to Rust
would carry every one of them across.

| Defect | Where it lives in 0.2.x | Consequence |
| --- | --- | --- |
| The agent loop is one builtin among twenty-six | `ctx.llm.agent_turn()` | Everything an agent needs that the builtin does not provide — planning, memory, compaction, retries — is reimplemented in userland `.star` with no runtime support |
| The loop returns a bare `str` | `module_llm.go:677` | A caller cannot tell "the model finished" from "we exhausted `max_iterations`" from "the model returned empty text"; the last two are reported as the same error and all partial work is discarded |
| The handler context is a 26-member god object built by hand in two places | `ctx_run.go:152`, `module_llm.go:867` | Already diverged (UI nesting depth); a module added to one and not the other is silently missing inside agentic tool calls |
| No cancellation, no budget | — | An agent that loops costs whatever it costs; Ctrl-C leaves the session half-written |
| No permission boundary | `shell_exec` is an ordinary tool | An LLM-driven tool that shells out is the product's central safety question and it has no answer |
| Missing tool arguments are filled with zero values | `executeToolForAgentic` | A model that omits a required `int` gets `0` and a plausible wrong answer instead of a correction |
| Sessions are implicit ambient state | `m.currentSession` | Parent/child relationships are positional and invisible to the script |
| Tool-call de-duplication only runs when sessions are on | `module_llm.go:521` | With `use_session=False`, duplicate streamed tool calls execute twice |
| Diagnostics go to `log.Printf` | 10 call sites in `module_llm.go` | Writes straight through the Bubble Tea frame and corrupts the display |
| Retry treats every error as retryable | `retry.go` | A `401` costs 30 seconds of backoff before it surfaces |

0.3.0 is a redesign because this list is a design, not a backlog.

## 3. Execution model

### 3.1 The central constraint

`starlark-rust` evaluators are `!Send`. A Starlark value cannot cross a thread
boundary, and an `Evaluator` cannot be resumed on another thread. Everything
about concurrency in this design follows from that one fact, so it is stated up
front rather than discovered late.

The consequence: **Starlark is never concurrent; Rust is.** A script cannot
spawn two closures and join them. What it can do is hand the engine two *agent
declarations* and receive two results, because an agent's execution lives in
Rust and only its declaration lives in Starlark.

### 3.2 Threading

```text
                 main thread (tokio)
                         |
                  ratatui render loop
                         |
      +------------------+-------------------+
      |                  |                   |
 spawn_blocking     spawn_blocking      tokio tasks
 script thread      script thread       HTTP, SQLite
 (Evaluator A)      (Evaluator B)       embeddings
      |                  |
  block_on(..)      block_on(..)
      |                  |
      +---- AgentEngine (async, Send) ------+
```

- Each script invocation owns one blocking thread and one `Evaluator`.
- Builtins that perform I/O are thin, synchronous wrappers over async engine
  calls via a `tokio::runtime::Handle`. From the script's point of view
  `agent.run(...)` simply blocks; underneath it is an async state machine.
- `meow.parallel([...])` takes agent *declarations*, not closures. The engine
  runs each on its own blocking thread with its own evaluator, and joins.
- Cancellation is a `CancellationToken` threaded through every engine call.
  `Ctrl-C` cancels the token; in-flight HTTP is aborted, the session is marked
  `cancelled`, and the builtin returns a `Cancelled` error that unwinds the
  script.

### 3.3 Why not make Starlark async

Two alternatives were considered and rejected.

*Async Starlark builtins.* `starlark-rust` has no async evaluation hook, and
adding one means forking it. The blocking-thread bridge costs one OS thread per
concurrent agent — a rounding error next to the latency of the model call it is
waiting on.

*Pure declarative configuration, no handlers.* Attractive, and wrong: the
useful automations are glue. Reading a diff, branching on whether tests pass,
formatting a report — these are imperative, and pushing them into declarative
config reinvents a worse language. Starlark stays imperative; only the
*concurrency* is taken away from it.

## 4. Crate layout

A Cargo workspace. Dependency direction is strictly downward — no crate depends
on one listed above it.

```text
crates/
  meow-cli          binary; clap, config discovery, TUI wiring, process lifecycle
  meow-ui           ratatui widgets, the event sink, rendering of agent transcripts
  meow-star         Starlark runtime: dialect, loader, module registry, `meow` global
  meow-agent        the engine: turn loop, tool dispatch, budgets, compaction, cancellation
  meow-tools        built-in tool implementations: fs, shell, git, http, search, index
  meow-policy       the permission boundary: rule matching, approval prompts, audit
  meow-index        chunking, embeddings, HNSW, retrieval
  meow-llm          provider-agnostic traits and wire types; streaming; retry; caching
  meow-provider-*   anthropic, openai, gemini, llama, copilot, openrouter, voyage
  meow-store        SQLite: sessions, events, cache, index tables, migrations
  meow-core         domain types shared by everything: Session, Event, Usage, Budget, Model
```

Two rules make the layering real rather than aspirational, both enforced by
`cargo-deny` and a workspace lint:

- `meow-core` has no dependency on any other workspace crate and no I/O.
- `meow-star` depends on `meow-agent`, never the reverse. The engine does not
  know Starlark exists. This is what makes the engine testable without a script
  and what would let a second frontend (a config file, an HTTP API) drive it.

In 0.2.x the equivalent boundary is broken: `internal/core/starlark` imports
`internal/adapters/gateway` directly. That must not be reproduced.

### 4.1 The engine boundary

```rust
// meow-agent
pub struct AgentSpec {
    pub model: ModelRef,
    pub system: Option<SystemPrompt>,
    pub tools: ToolSet,
    pub budget: Budget,
    pub compaction: CompactionPolicy,
    pub output: OutputSpec,       // free text, or a JSON schema to satisfy
    pub on_tool_error: ToolErrorPolicy,
}

pub struct AgentRun {
    pub task: String,
    pub session: SessionHandle,
    pub cancel: CancellationToken,
}

#[async_trait]
pub trait Engine {
    async fn run(
        &self,
        spec: &AgentSpec,
        run: AgentRun,
        events: &mut dyn EventSink,
    ) -> Result<AgentOutcome, EngineError>;
}

pub struct AgentOutcome {
    pub stop: StopReason,          // Finished | BudgetExhausted | Cancelled | ToolAborted
    pub text: String,              // always populated, even on a non-Finished stop
    pub value: Option<JsonValue>,  // present when OutputSpec::Schema was satisfied
    pub usage: Usage,
    pub steps: Vec<Step>,
    pub session: SessionId,
}
```

`AgentOutcome` is the whole answer to the "returns a bare string" defect.
`stop` is always present, `text` is always populated so partial work survives a
budget stop, and `steps` is the transcript a script can inspect or render
without re-reading the session store.

`EventSink` is the one place streaming crosses a boundary. `meow-ui` implements
it to draw; `meow-star` implements it to invoke a script callback; tests
implement it to collect. Neither the engine nor the providers know which.

## 5. Tools and the permission boundary

### 5.1 One kind of tool

0.2.x has tools, commands, and agents as three overlapping concepts with one
struct behind them. 0.3.0 has one concept and two ways to surface it:

- A **tool** is a name, a parameter schema, and an implementation. The
  implementation is either Rust (`meow-tools`) or a Starlark handler.
- Exposing a tool on the CLI (`meow.command`) and offering it to a model
  (`tools = [...]`) are two independent decisions about the same object.

An agent is not a third thing. `meow.agent(...)` produces a value that is itself
callable as a tool, which is how sub-agents work: you put an agent in another
agent's `tools` list.

### 5.2 Parameters

Missing arguments are never invented. When a model omits a required parameter,
the tool is not invoked; the engine returns a structured correction to the model
(`missing required parameter 'path' (string): absolute or workspace-relative
file path`) and the turn continues. Optional parameters fall back to their
declared default, and a parameter with no default is absent rather than zeroed,
which is representable because the schema is typed and `None` is distinct from
`0`.

### 5.3 Policy

Every tool call passes through `meow-policy` before it executes. A rule matches
on tool name plus a tool-specific selector and yields `Allow`, `Ask`, or `Deny`.

```python
meow.policy(
    allow = [
        "fs.read",
        meow.rule("fs.write", paths = ["src/**", "tests/**"]),
        meow.rule("shell", commands = ["cargo *", "git status", "git diff"]),
    ],
    ask = [meow.rule("shell", commands = ["git push *"])],
    deny = ["http.*", meow.rule("fs.write", paths = [".git/**", "**/*.key"])],
)
```

Three properties matter:

- **Deny wins, then ask, then allow.** No rule matching means deny. A tool an
  agent was never granted is not reachable by prompt injection.
- **The decision is recorded.** Every call, its decision, and the matching rule
  land in the session as an auditable event, so `meow session show` explains
  what an agent was permitted to do and why.
- **`Ask` is interactive only.** Under `--yes`, `Ask` degrades to `Deny` rather
  than to `Allow`, so an unattended run in CI cannot silently escalate.

This is the single largest addition over 0.2.x, and the reason it belongs in the
runtime rather than in a `.star` library is that a library cannot be trusted by
the thing it is supposed to constrain.

## 6. Sessions

Sessions become explicit values rather than ambient state.

```python
s = meow.session("triage")          # create; or meow.session.resume(id)
r1 = investigator.run(task, session = s)
r2 = fixer.run(r1.text, session = s.child("fix"))
```

The store is SQLite (`rusqlite`, bundled, WAL). The event log is append-only and
typed: `UserMessage`, `AssistantMessage`, `ToolCall`, `ToolResult`,
`PolicyDecision`, `Compaction`, `Usage`. Compaction does not delete; it appends
a `Compaction` event that supersedes a range, so a compacted session can still
be replayed in full. That is a property 0.2.x's `mark_obsolete` gestures at and
does not guarantee.

Resumability falls out: `meow session resume <id>` replays the log into a
message list and continues. It is the reason `--continue` can exist at all.

## 7. Budgets, retries, and failure

`Budget` bounds a run on four axes — wall-clock, total tokens, estimated cost,
and iterations — and whichever binds first produces
`StopReason::BudgetExhausted` with the partial transcript intact. Budgets nest:
a sub-agent's spend counts against its parent's remaining budget, so a fan-out
cannot exceed the top-level cap.

Retry is classified rather than blanket. `meow-llm` maps every provider error
into `Transient` (429, 5xx, connection reset — retry with jitter),
`Fatal` (401, 403, 400, schema rejection — surface immediately), and
`QuotaExhausted` (billing — surface with the billing hint). 0.2.x retries
everything that is not a hard quota error, which is why an invalid API key costs
half a minute before it is reported.

Diagnostics go through `tracing` with a TUI-safe writer that parks output above
the live frame. `println!` and `eprintln!` are denied in every crate but
`meow-cli`, by lint.

## 8. Errors

`thiserror` in libraries, `miette` at the boundary. Starlark diagnostics carry
source spans, so a schema mistake renders as:

```text
  × unknown parameter type "integer"
   ╭─[.meow/agents/triage.star:14:24]
14 │     params = { "count": meow.param("integer") },
   ·                                    ────┬────
   ·                                        ╰── did you mean "int"?
   ╰────
```

This is item 13 of the 0.2.x TODO ("better error messages"), and it is close to
free once the runtime keeps spans instead of formatting strings.

## 9. Dependency map

| Concern | 0.2.x (Go) | 0.3.0 (Rust) | Risk |
| --- | --- | --- | --- |
| Starlark | `go.starlark.net` | `starlark-rust` | **High** — different API shape; `!Send` values; `load()` needs a custom `FileLoader` |
| CLI | cobra | `clap` (derive) | Low |
| TUI | bubbletea + lipgloss | `ratatui` + `crossterm` | Medium — the Elm architecture does not port; the UI is rewritten, not translated |
| Markdown | glamour | `pulldown-cmark` + `syntect` | Low |
| Highlighting | chroma | `syntect` | Low |
| SQLite | `ncruces/go-sqlite3` (wasm) | `rusqlite` (bundled) | Low — and a real gain: no wasm interpreter in the hot path |
| Vectors | `coder/hnsw` | `hnsw_rs` or `usearch` | Medium — recall parity needs a test against the existing index |
| Tokenizer | `tiktoken-go` | `tiktoken-rs` | Low |
| HTTP | net/http | `reqwest` + `rustls` | Low |
| Anthropic / OpenAI / Gemini | official SDKs | **hand-rolled over `reqwest`** | Medium — no first-party Rust SDKs; streaming and tool-call framing must be written per provider |
| Async | goroutines | `tokio` | Medium — see §3 |
| Release | goreleaser | `cargo-dist` | Low |

The two entries in bold are where the schedule risk lives, and §11 prices them.

## 10. What carries over

The `.meowg1k/` tree is roughly 10,000 lines of Starlark, and most of its value
is prompts and formatting rather than control flow. It does **not** port
unchanged — the API redesign in `0.3.0-starlark-api.md` is deliberately breaking
— but the prompts, the diff-chunking heuristics, and the output templates move
across as text.

The `.star` libraries that exist only to work around missing runtime features —
`compaction.star`, `memory.star`, `planning.star`, `agent.star`, roughly 2,500
lines — are deleted, not ported. Their functionality becomes engine features.
That is the clearest single measure of whether this redesign is worth doing.

## 11. Cost

Measured against the current tree: 28,300 lines of non-test Go, 38,000 lines of
test Go, 10,000 lines of Starlark.

| Area | Go LOC | Estimate | Notes |
| --- | --- | --- | --- |
| Workspace skeleton, mise, CI, renovate, cargo-dist | — | 3–4 days | §12 |
| `meow-core` domain types | 1,300 | 1 week | Mostly mechanical |
| `meow-store` SQLite + migrations + session log | 2,400 | 2 weeks | Schema changes for the append-only log |
| `meow-llm` + six providers | 4,700 | 4–5 weeks | Hand-rolled SDKs; streaming and tool framing differ per provider |
| `meow-agent` engine | 1,000 | 3 weeks | Larger than its Go counterpart because budgets, cancellation, and compaction move in |
| `meow-policy` | 0 | 1.5 weeks | New |
| `meow-star` runtime + module surface | 8,400 | 5–7 weeks | The dominant risk; see §3.1 |
| `meow-tools` | 1,500 | 2 weeks | |
| `meow-index` RAG | 1,800 | 2 weeks | Recall parity testing against the 0.2.x index |
| `meow-ui` | 1,900 | 3 weeks | Rewrite, not a port |
| `meow-cli` | 1,400 | 1 week | |
| Tests to 65% parity | 38,000 | 4–5 weeks | Overlaps the above; `insta` snapshots carry a lot of it |
| Rewriting `.meow/` against the new API | 10,000 | 2 weeks | Prompts survive, control flow does not |
| Docs, packaging, release | — | 1 week | |

**Solo, focused, AI-assisted: 4–6 months.** Compressible to roughly 3 by
shipping two providers instead of six and deferring RAG, both of which are
additive and neither of which is on the critical path.

The estimate is dominated by `meow-star`, and the honest uncertainty there is
±3 weeks depending on how much of `starlark-rust`'s value model fights the
module design. That question is answerable in about two days of spiking, and
doing so before committing to the schedule is the highest-value thing on this
page.

### 11.1 Is it worth it

Rust buys, concretely: a real permission boundary that a scripting layer cannot
subvert; genuine parallel sub-agents; startup and memory that suit a tool
invoked from a shell prompt; single static binaries without a wasm SQLite; and
error reporting with source spans. It does not buy raw model latency, which is
where the wall-clock actually goes.

The honest counter-argument is that every item in §2 is fixable in Go for
perhaps six weeks, and the rewrite costs four to six months. The case for the
rewrite rests on the permission boundary and the concurrency model being
architectural rather than incremental — and on the judgement that the Starlark
API needs a breaking redesign regardless, which removes the compatibility
argument for staying put.

## 12. Toolchain, CI, and dependency automation

Task is dropped; `mise` is the single entry point, following the `vlie` layout.

```toml
# mise.toml
[tools]
rust = { version = "stable", components = "rust-analyzer,clippy,rustfmt" }
"cargo:cargo-nextest" = "latest"
"cargo:cargo-deny" = "latest"
"cargo:cargo-machete" = "latest"
"cargo:cargo-dist" = "latest"
"npm:markdownlint-cli2" = "latest"
"npm:prettier" = "latest"
gh = "latest"

[tasks.check]
run = "cargo clippy --workspace --all-targets -- -D warnings"
[tasks.test]
run = "cargo nextest run --workspace"
[tasks.fmt]
run = "cargo fmt --all"
[tasks.fmt-check]
run = "cargo fmt --all -- --check"
[tasks.deny]
run = "cargo deny check"
[tasks.unused-deps]
run = "cargo machete"
[tasks.build]
run = "cargo build -p meow-cli"
[tasks.lint-md]
run = "markdownlint-cli2 '**/*.md' '#target'"
[tasks.all]
depends = ["fmt-check", "check", "test", "deny", "lint-md"]
```

`rust-toolchain.toml` pins the channel so CI and local agree.

CI mirrors the 0.2.x stage structure — fast gate, then full lint, security,
tests, build matrix — with the Go steps replaced:

| 0.2.x stage | 0.3.0 equivalent |
| --- | --- |
| `golangci-lint --enable-only=...` | `cargo clippy -D warnings` on the fast gate |
| `golangci-lint run` full | `cargo clippy --all-targets` + `cargo fmt --check` |
| gosec, govulncheck | `cargo deny check` (advisories, licences, bans) + `cargo audit` |
| gitleaks, trivy | unchanged |
| `task check:test` matrix | `cargo nextest run` on linux/macos/windows |
| cross-compile matrix | `cargo-dist` build matrix |
| goreleaser + cosign + syft | `cargo-dist` + cosign + syft, unchanged otherwise |

Keep the existing SHA-pinned actions and the `security-events` permission as
they stand after `v0.2.1`; only the job bodies change.

Renovate needs its manager set swapped, not its policy:

```jsonc
{
  "extends": ["config:recommended", ":dependencyDashboard"],
  "enabledManagers": ["cargo", "github-actions", "mise", "npm"],
  "packageRules": [
    { "matchManagers": ["cargo"], "matchUpdateTypes": ["minor", "patch"],
      "groupName": "cargo dependencies", "automerge": true },
    { "matchManagers": ["cargo"], "matchUpdateTypes": ["major"],
      "dependencyDashboardApproval": true },
    { "matchManagers": ["github-actions"], "pinDigests": true }
  ]
}
```

The `dependencyDashboardApproval` rule on major bumps is not boilerplate — it
is the direct lesson of PRs #85 and #96, which bumped five Charm crates and
openai-go across major versions without touching a single import and left `dev`
unbuildable for two months. Under Cargo the same class of PR fails
`cargo check` instead of silently merging, but requiring approval for majors
costs nothing and removes the failure mode entirely.

## 13. Sequencing

Each phase ends with something runnable; none is a big-bang merge.

1. **Spike (2 days).** `starlark-rust` with three real modules and one
   `block_on` builtin. Answers the §11 uncertainty before anything else is
   committed to.
2. **Skeleton.** Workspace, mise, CI, renovate, `cargo-dist`, `meow-core`.
3. **Vertical slice.** One provider, no tools, no session: `meow run "hello"`
   streams tokens to the terminal. Proves the threading model end to end.
4. **Engine.** Tool dispatch, `AgentOutcome`, budgets, cancellation, policy.
5. **Persistence.** Sessions, events, resume.
6. **Surface.** The full Starlark API, remaining providers, RAG, the TUI.
7. **Port `.meow/`.** Rewrite the shipped agents against the new API; they are
   the acceptance test.

The rewrite lives on a `rust` branch with its own CI until phase 5. `dev` keeps
building the Go tree until `v0.3.0` is tagged, so `v0.2.1` stays fixable.
